# 台科電 DEM540N — Modbus RTU 通訊手冊

> 本手冊只寫**最終結論**（不含開發過程與歷史版本）。
> 未經實測確認的項目會明標「**未確認**」，請不要當成規格使用。

---

## 1. 通訊參數

| 項目 | 值 |
|---|---|
| 介面 | RS485 轉 USB（FTDI `0403:6001`）；Linux `/dev/ttyUSB*`、Windows `COM*` |
| 鮑率 | **2400 bps** |
| 資料格式 | 8N1 |
| 協議 | Modbus RTU |
| CRC | CRC-16/Modbus（多項式 `0xA001`、初值 `0xFFFF`、**低 byte 先送**） |
| 幀邊界 | 標準 RTU：幀內位元組間隔 < 1.5 字元時間（2400 bps ≈ 6.25 ms）；**3.5 字元時間（≈14.6 ms）** 為幀界 |
| 錯誤行為 | 這顆表**不回 Modbus exception**；錯誤一律表現為「沒有回應」或 CRC 不正確 |

---

## 2. 匯流排使用規則

1. **同一條 RS485 同時只能有一個主站。**
   - **只讀（旁聽）**：可以與既有主站並存。
   - **要主動發送前**：先確認沒有其他主站在講話（例如連續 3 秒匯流排上沒有任何位元組）才接手。
2. **要先知道「站號 ↔ 現場位置」對應，並確認哪一顆不能動。**
   控制類指令（FC05／FC10）會直接改變現場供電與計費，對錯誤的電表發送可能造成停電事故。
   不確定時先只做 FC03 讀取。
3. **USB 轉接頭的 latency timer（常見 16 ms）會把連續位元組分批送進電腦。**
   分析側錄資料時**不要用「位元組間隔」切幀**，要用 **CRC 掃描重建幀**（見 §8）。
4. RS485 為半雙工：**一個請求的回應收完，才能送下一個請求**。

## 3. FC03 — 讀取

```
TX  [ID] 03 00 00 00 18 [CRC]          ← 從 0x0000 讀 24 個暫存器（48 bytes）
RX  [ID] 03 30 [48 bytes] [CRC]        ← 固定 53 bytes
```
範例（ID 01）：請求 `01 03 00 00 00 18 45 C0`

### 3.1 回應封包結構

| 區段 | 長度 | 內容 |
|---|---|---|
| ID | 1 | 站號 |
| 功能碼 | 1 | `03` |
| Byte count | 1 | `30`（= 48 bytes） |
| Data | 48 | 24 個暫存器，每個 **高 byte 先**（big-endian） |
| CRC | 2 | 低 byte 先 |

### 3.2 暫存器地圖

| Reg | 意義 | 換算 |
|---|---|---|
| 0 | 累積度數 **Low Word** | `kWh = ((Reg1 << 16) \| Reg0) / 100`（一般二進位，**不是 BCD**） |
| 1 | 累積度數 **High Word** | 同上 |
| 2 | **恆為 0** | — |
| **3** | **狀態旗標** | 見 §7 |
| 4 ~ 21 | **恆為 0** | 這顆表**沒有**電壓／電流／頻率／功率因數暫存器 |
| 22 | 剩餘度數 **Low Word** | `餘度 = ((Reg23 << 16) \| Reg22) / 100` |
| 23 | 剩餘度數 **High Word** | 同上 |
| ≥ `0x0080` | **未確認** | 內容與用途未經實測確認，不要依賴 |

- 單位：**÷100**（刻度 0.01 度）。例：`C1 5B` → `0xC15B = 49499` → **494.99 度**。
- 因為刻度是 0.01 度，**以 10 分鐘間隔取樣時，平均功率低於 60 W 的負載完全看不出來**（物理限制，不是故障）。

### 3.3 解讀實例

`01 03 30 | AC1D 0003 | 0000 | 05A1 | …(Reg4~21 全 0)… | 07D0 0000 | CRC`

| 欄位 | 結果 |
|---|---|
| Reg0 `AC1D`、Reg1 `0003` | `0x0003AC1D = 240669` → 累積 **2406.69 kWh** |
| Reg3 `05A1` | 非儲值模式、供電中（§7） |
| Reg22 `07D0`、Reg23 `0000` | `0x000007D0 = 2000` → 餘度 **20.00 度** |

## 4. FC05 — 線圈控制

```
TX  [ID] 05 [Addr H] [Addr L] [Val H] [Val L] [CRC]
RX  [ID] 05 [Addr H] [Addr L] [Val H] [Val L] [CRC]     ← 原封不動回傳 8 bytes
```

### 4.1 線圈一覽

| 位址 | 值 | 功能 | 適用模式 |
|---|---|---|---|
| `0x000A` | `0x0000` | 前置清除（用途未公開；**操作 `0x000B` 前必發**） | 任意 |
| `0x000B` | `0xFF00` | **進入**儲值（預付）模式 | 非儲值 |
| `0x000B` | `0x0000` | **退出**儲值模式 | 儲值 |
| `0x0002` | `0xFF00` | 強制開電（繼電器 ON） | **非儲值專用** |
| `0x0002` | `0x0000` | 強制關電（繼電器 OFF） | **非儲值專用** |
| `0x0052` | `0xFF00` | 儲值模式開電（繼電器 ON） | **儲值專用** |
| `0x0052` | `0x0000` | 儲值模式關電（繼電器 OFF） | **儲值專用** |

- ⚠️ **`0x0002` 在儲值模式下無效**（會看似成功但繼電器沒動作）。儲值模式控電只能用 `0x0052`。
- 從未觀察到 `0x000A = 0xFF00`。

### 4.2 送法（必要）

| 規則 | 值 |
|---|---|
| 同一條指令 | **連送兩次**，間隔 **≈50 ms** |
| 不同指令之間 | **≥ 0.5 秒**（實測 0.5–1.7 秒） |
| 每條送出後 | **先讀掉 8-byte echo**，再送下一條 |
| 收尾 | 序列結束後，等一個匯流排空檔再進行其他通訊 |

### 4.3 完整序列

| 動作 | 序列 | 效果 |
|---|---|---|
| 強制開電 | `0x000A=0` → `0x000B=0` → `0x0002=0xFF00` | 退出儲值（若在）＋強制供電 |
| 強制關電 | `0x000A=0` → `0x000B=0` → `0x0002=0` | 退出儲值（若在）＋強制斷電 |
| 進入儲值模式 | `0x000A=0` → `0x000B=0xFF00` | 進入預付模式；**繼電器狀態不確定** |
| 退出儲值模式 | `0x000A=0` → `0x000B=0` | **只退出，不控制繼電器**（見 §9-3） |
| 儲值模式開電 | `0x0052=0xFF00` | 儲值模式下送電 |
| 儲值模式關電 | `0x0052=0x0000` | 儲值模式下斷電 |

**是否在儲值模式**：看 Reg3 是否為 `0x01D1` / `0x00C0` / `0x00D0`（§7）。

## 5. FC10 — 寫入剩餘度（儲值）

```
TX  [ID] 10 00 16 00 02 04 [Low H] [Low L] [High H] [High L] [CRC]
RX  [ID] 10 00 16 00 02 [CRC]          ← 8 bytes，實測約 100 ms 後回來
```

| 項目 | 值 |
|---|---|
| 位址 | `0x0016`（2 個暫存器 / 32-bit） |
| 排列 | **Low Word 在前、High Word 在後** |
| 單位 | ×100（`50.00` 度 → `5000 = 0x1388`） |
| 寫入值 | **新的總餘度（絕對值）**，不是增量 |
| 前置條件 | 必須已在**儲值模式**（§4.3 進入儲值模式） |

範例（ID 03、寫 494.99 度）：
```
TX  03 10 00 16 00 02 04 C1 5B 00 00 35 1E
RX  03 10 00 16 00 02 A1 EE
```

### 5.1 必要時序（不遵守會「假成功」）

1. **送出 FC10 後，必須先收下它的 8-byte 回應，才能送下一個請求。**
   若不等回應就送下一個請求（例如立刻用 FC03 讀回），會發生半雙工碰撞：
   **電表回 ACK，但這次寫入不會套用**（餘度不變）。
2. **寫入值就是絕對值；重送相同值是安全的（冪等）**，不會變成加兩次。

### 5.2 成功判定（不可只看 ACK）

一個完整的寫入流程必須包含**讀回驗證**：

```
1. FC03 讀當前餘度 → before
2. 目標 target = round(before + 要加的度數, 2)
3. FC10 寫 target（絕對值）→ 收下 8-byte 回應
4. FC03 讀回 → |讀回 − target| ≤ 0.01 才算成功
5. 不符 → 重送 FC10（只重送 FC10，建議最多 2~3 次）
```

- **不可**只憑 FC10 的回應就宣佈成功。
- 比較建議以「分」為單位（`round()` 與整數轉換在 `.xx5` 可能差 1 分）。
- 只要條件符合，**FC10 不需要在前後夾任何模式指令**（模式指令屬於 §4 的模式切換）。

## 6. FC10 — 修改裝置站號

**位址是 `0x0030`（48），不是 `0x0005`**（`0x0005` 只能讀目前站號）。三步驟，中間不可插任何指令：

```
① 啟用寫入    FC05  0x0030 = 0x0000             → 送到【舊】站號
② 寫入站號    FC10  0x0030 數量 1 資料 [新ID][0]  → 送到【舊】站號
③ 確認並停用  FC05  0x0030 = 0xFF00             → 送到【新】站號   ⚠️
```

- ⚠️ **③ 必須送到「新」站號**：站號在 ② 送出的當下就改變了；送舊站號會落空，
  電表會停在「寫入已啟用」狀態。
- ⚠️ **① 是硬性必要條件**：少了它，② 會被 ACK 但不生效。
- ⚠️ **② 會用掉「啟用」**（一次性）；要再改一次必須重做 ①。久放不用的啟用也會失效。
- 驗證：用**新站號**讀 `0x0005`，應等於新站號。

## 7. Reg 3 狀態碼

| Reg 3 值 | 名稱 | 模式 | 繼電器 | 備註 |
|---|---|---|---|---|
| `0x05A1` | 供電 | **非儲值** | ON | 最常見 |
| `0x01D1` | 預付 | **儲值** | ON | |
| `0x00C0` | 預關 | 儲值 | OFF | 儲值模式下按「斷電」 |
| `0x00D0` | 欠費 | 儲值 | OFF | 餘度為 0 |
| `0x0080` | 強關 | 非儲值 | OFF | 強制關電 |
| `0x0181` | （未定義） | 過渡 | — | **只在「退出儲值模式」的過渡期出現**，數秒後才結束 |
| `0x0000` | 斷電 | — | OFF | **實務上未出現過**；遇到請原樣顯示，不要硬套模式 |

**重點：同一個值同時編碼「模式」與「供電」兩件事。**
`0x05A1`（非儲值供電）與 `0x01D1`（儲值供電）**都是「有電」**，但模式不同；
顯示或判斷時請把兩個維度分開，不要用單一欄位同時表達。

- **在儲值模式** = `0x01D1` / `0x00C0` / `0x00D0`。
- 未知值請原樣顯示（例如 `未知(0x0181)`），不要對應到錯誤的模式。

## 8. 時序參考值

| 量 | 實測值 |
|---|---|
| FC03：請求尾 → 回應頭 | **≈30 ms** |
| FC10：請求尾 → 8-byte 回應頭 | **≈100 ms** |
| FC05：同一指令連送兩次之間 | **≈50 ms** |
| FC05：不同指令之間 | **0.5–1.7 秒** |
| 判定匯流排空檔 | 連續 **3 秒** 無位元組 |

**側錄分析**：逐 byte 記錄時務必連時間戳一起存；重建幀請用 **CRC 掃描**
（逐一位置嘗試 8 / 13 / 53 / 61 bytes 等已知長度，CRC 正確就接受並跳過），
不要用位元組間隔切幀（USB 分批會把一個幀拆成好幾段）。

---

## 9. 注意事項（規則）

1. **FC10 不等回應就送下一個請求** → 電表 ACK 但不套用（§5.1）。
2. **在儲值模式下用 `0x0002` 控電** → 無效；要用 `0x0052`。
3. **「退出儲值模式」不會自動復電**：只送 `0x000B=0` 之後，繼電器可能停在 OFF（強關）。
   要「退出且保持供電」請用**強制開電**序列（本身已含退出儲值）。
4. **改站號少了「啟用」或把 ③ 送到舊站號** → 站號不變，或電表卡在「寫入已啟用」（§6）。
5. **兩個主站同時發送** → 封包互撞、雙方都失敗；接手前先確認匯流排空檔（§2）。
6. **只看 FC10 的回應就宣佈成功** → 必須 FC03 讀回驗證（§5.2）。
7. **用位元組間隔切幀** → USB latency timer 會導致誤切（§8）。
8. **把「模式」與「供電」混成一個欄位** → 會誤判儲值模式（§7）。

## 11. 實作後的驗證清單

**只讀**

1. 每顆表都回 53 bytes、CRC 正確；請求尾→回應頭 ≈30 ms。
2. Reg 2 與 Reg 4~21 全為 0（若某顆不是 0，先記錄該顆再繼續）。
3. Reg3 都能在 §7 找到；未知值原樣顯示。

**寫入**（先確認站號↔現場位置，且只對允許的對象）

4. FC05：每條是否連送兩次、不同指令間隔 ≥0.5 秒、echo 是否讀掉。
5. 狀態轉移與 §7 一致；特別確認「退出儲值」之後是 `0x0080` 還是 `0x05A1`（過渡期可能出現 `0x0181`）。
6. FC10：封包為 `[ID] 10 00 16 00 02 04 [Low][Low][High][High]`、Low Word 在前、值是絕對值、寫入前已在儲值模式。
7. **反面測試**：FC10 後不等回應就立刻讀取 → 應觀察到餘度**沒有變**（驗證時序的重要性）。
8. **正面測試**：正常流程連續寫入 10 次 → 10/10 成功且每次讀回相符。
9. 「退出且保持供電」：確認最終 Reg3 是 `0x05A1`（供電），不是 `0x0080`（強關）。
10. 測試後把模式、供電、餘度還原，並比對測試前後狀態。
